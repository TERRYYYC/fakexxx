# Primary-source evidence ledger

This ledger evaluates the claims needed by [issue #66](https://github.com/TERRYYYC/fakexxx/issues/66). It uses Android SDK/AOSP and official LSPosed sources only. Source validity and direct fit to QWY are separate: an upstream symbol can prove that a hook point exists without proving that an OEM build preserves the same call graph.

## Lifecycle and failure evidence

| Event | Observable consequence | Safe verdict |
|---|---|---|
| kernel boot changes | `/proc/sys/kernel/random/boot_id` changes | first observation NONE; never compare old sequence |
| system_server/module oracle restarts in the same boot | new random `oracleInstanceId` | first observation NONE; never compare old sequence |
| LSPosed hook callback throws | callback catches/poisons before returning; platform call continues | sticky unhealthy + NONE |
| required hook cannot be resolved or installed | required mask differs from installed mask | NONE |
| build fingerprint is not attested | health `BUILD_UNATTESTED` | NONE |
| QWY registrar/oracle Binder dies | proxy cleared; outstanding semantic mutation aborted and session marked uncertain | NONE until a new session explicitly reconciles |
| mutation overlaps either snapshot | odd sequence or PRE/POST mismatch | NONE |
| sequence regresses under the same instance ID | invariant violation | sticky NONE for that instance |
| storage crashes before revision+ACK commit | neither side of the local transaction is durable | retry may repeat work, but cannot silently skip the bump |

## Unknowns requiring exact-build evidence

1. Whether the target Android 15 OEM image preserves every AOSP internal call path above, including the API-35 Access Checking implementation and its lifecycle mutations.
2. Whether the selected LSPosed build admits the module into `system_server` under the target SELinux policy.
3. The exact build fingerprint(s) that may be placed in the attestation allowlist.
4. Boot-time package/service availability and reconnect behavior on the target image.
5. Whether vendor location or AppOps extensions add mutation paths outside the AOSP mask.

The kernel boot epoch source is `/proc/sys/kernel/random/boot_id`: AOSP VTS describes it as a read-only random UUID generated each boot, and Android 15 SELinux labels/grants it for domain reads. `Settings.Global.BOOT_COUNT` is not an equivalent fallback because `PowerManagerService` increments it only at boot phase 600. An unreadable/malformed kernel boot ID is therefore unhealthy, while `oracleInstanceId` separately detects same-boot producer restart.

These unknowns prevent a production FULL claim in this pass; they do not justify weakening the oracle. The safe decision is a compile- and JVM-testable pilot whose production health remains false until exact-build evidence is added.
